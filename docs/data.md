# 数据格式与质量契约

项目读取本地 CSV 或 Parquet（`.parquet`、`.pq`）。股票代码按字符串处理，避免把 `000001` 变成整数。每份数据可以包含多只股票；每行表示一只股票的一个时点。

## 日频行情

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `date` | `YYYY-MM-DD` | 无时区交易日期，不包含日内时间 |
| `symbol` | 字符串 | 稳定、非空的股票标识，建议附交易所后缀 |
| `open` | 浮点数 | 当日开盘价，有限且大于零 |
| `close` | 浮点数 | 当日收盘价，有限且大于零 |
| `volume` | 数值 | 全日成交股数，有限且非负 |
| `tradable` | 可选布尔值 | 默认 `true`；也接受 `false`、`1`、`0` |

例如：

```csv
date,symbol,open,close,volume,tradable
2024-01-02,000001.SZ,10.00,10.12,1200000,true
2024-01-02,600000.SH,8.10,8.06,900000,true
```

这是格式示例，只有一天的数据不足以计算因子。每个 `(date,symbol)` 必须唯一；输入顺序可以任意，加载后会按日期、代码排序。

`tradable=False` 应用于已知不可交易的观察日；停牌期间的沿用价格不应伪装成正常零收益。因子会排除这些信号和受影响的完整历史窗口。对于缺少整行的数据，程序通过共同交易日历保留空档，不能用前一日价格悄悄补齐。

实际可交易性取决于时点和方向。单一日频标记只能表达简化约束；涨跌停、盘中复牌、开盘无法买入但收盘可卖出等情况需要更细的执行模型。

## 一分钟尾盘行情

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `timestamp` | ISO 时间 | 一分钟条的**开始时间** |
| `symbol` | 字符串 | 与日频一致 |
| `open` | 浮点数 | 这一分钟开盘价，有限且大于零 |
| `close` | 浮点数 | 这一分钟收盘价，有限且大于零 |
| `volume` | 数值 | 这一分钟成交股数，有限且非负 |

例如第一根条可以写为：

```csv
timestamp,symbol,open,close,volume
2024-01-02T14:00:00+08:00,000001.SZ,10.05,10.06,15000
```

默认市场时区为 `Asia/Shanghai`。带时区时间会转换到市场时区；不带时区时间会按市场本地时间解释。一个文件不能混用带时区与无时区约定。时间必须精确到整分钟，不能带非零秒或微秒。

默认窗口包含 14:00、14:01、……、14:59，代表 14:00 至 15:00 的 60 个一分钟区间。14:59 条的收盘价是尾盘终点，14:00 条的开盘价是起点。**若供应商使用结束时间标签（14:01 至 15:00），须先统一转换到开始时间标签。** 不要直接把结束标签输入当作开始标签。

每个 `(timestamp,symbol)` 必须唯一。可以提供全日行情，窗口之外的分钟不影响尾盘聚合；也可以仅提供尾盘 60 根。少一根就是不完整窗口，其尾盘收益和成交量记为缺失。程序不会自动补零成交量、插值或前向填充价格。集合竞价的行情表达方式需要先与供应商核对，确保最后几分钟确实代表完整的收盘过程。

尾盘聚合为：

```text
tail_return = 最后一根.close / 第一根.open - 1
tail_volume = 窗口内每分钟.volume 之和
```

原始分钟价格在当日应连续、与日频收盘价一致；数据供应商的错误和日频、分钟口径冲突应在送入研究前核对。项目的格式校验不等于完整的行情审计。

## 交易日历

建议提供只有 `date` 列的 CSV 或 Parquet：

```csv
date
2024-01-02
2024-01-03
2024-01-04
2024-01-05
```

```bash
uv run cfpr run --daily data/daily.csv --intraday data/intraday.csv \
  --calendar data/calendar.csv --output outputs/research
```

日历应包含研究区间内完整、有序且唯一的交易所交易日。日频和分钟观测必须落在对应交易日内。没有显式日历时，使用日频行情中所有股票日期的并集；如果某个真实交易日对所有股票都缺失，并集也无法知道那一天本应存在。

程序以共同日历的交易日位置计算 $t-25$、$t-5$、$t+1$ 与 $t+5$。不会按单只股票删除缺失日期后再滚动，从而避免把停牌十天解释成相邻两个交易日。

## 复权与公司行动

入场开盘价、持有期间收盘价、标签价格与日频因子价格需要使用一致、可比较的总收益复权口径。分红、拆股、送股等事件不能成为虚假的回撤或五日收益。

尾盘收益在同一天计算，但过去 20 日的分钟基准和成交量基准仍受公司行动与数据供应商口径影响。成交量必须统一为股或统一的复权股数，不能日频用“手”、分钟用“股”；拆股前后应核对量的可比性。程序不自动进行公司行动复权。

若使用前复权数据，应核对研究结果对供应商历史重算的依赖；若使用原始价格，需要在外部明确计入分红与拆股。本项目没有内置公司行动或证券主数据服务。

## 股票池与缺失样本

实证研究需要保存每个日期当时可知的可投资股票池，包含历史退市股票，而不是把今天仍上市的股票向历史回填。日频 `tradable` 不等于完整的时点股票池管理功能。

默认前 25 个交易日属于预热期，尾盘基准另需至少 20 个完整历史窗口。实际停牌或缺失会延长单只股票的可用时间。缺少后续完整持有窗口时，不计算对应标签；回测不能用未来是否完整或未来涨跌表现来选择买入股票。

已持仓股票缺少估值价格，或计划离场时不可交易，当前回测会明确失败。应修正行情问题或扩展停牌、退市与延迟成交模型，而不是删除这些股票后重跑并称为无偏收益。

## 模拟数据

```bash
uv run cfpr generate --output data/demo --symbols 40 --days 160 --seed 42
```

生成器固定随机种子即可复现，产生价格连续的尾盘分钟条、与之匹配的日频收盘价和足够的成交量。它采用普通工作日序列，不包含真实交易所节假日。股票代码、价格、成交量与所有收益均为模拟值，未来收益没有按因子人为植入优势。

模拟文件适合检查安装、接口、时点、回测与报告是否能运行；不能用来证明该因子的市场预测力。
